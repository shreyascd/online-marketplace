1. Executive Summary

ShopLite is a robust, lightweight, and modular e-commerce marketplace platform engineered to bridge buyers and independent sellers seamlessly. Built using modern software design principles, the application demonstrates end-to-end full-stack capabilities, incorporating role-based access control (RBAC), multi-criteria catalog search and filtering, real-time inventory tracking with defensive concurrency safeguards, and an ACID-compliant transactional checkout mechanism.

Unlike overly complex monolithic or microservice frameworks that introduce significant operational overhead, ShopLite leverages standard Python libraries combined with Flask and SQLite. It avoids heavy Object-Relational Mappings (ORMs) in favor of high-performance, strictly parameterized SQL queries. This guarantees total transparency, zero SQL-injection vulnerabilities, fast page loads, and simplified local or containerized deployments.

Key Architectural Value Proposition: Complete separation of concerns between presentation, business rules, and persistent storage, coupled with hardened session validation and database-level transactional locks during inventory deduction.

2. System Architecture & High-Level Design

The system follows an adapted Model-View-Template (MVT) / Model-View-Controller (MVC) architectural pattern:

  • Presentation Layer (View/Template): Powered by Jinja2 and Bootstrap 5.3, providing a modern, mobile-responsive user interface with client-side interactivity, dynamic status badges, flash notifications, and contextual navigation bars.
  • Application Controller Layer (Controller): Implemented in app.py with Flask route decorators, HTTP request parsing, input sanitization, custom authentication wrappers, and response orchestration.
  • Data Layer (Model): Managed through database.py using SQLite3 with explicit connection lifecycle handlers (via Flask's g context), custom row factories for column-name access, foreign key enforcement, and explicit transaction isolation.

4. Database Design & Data Dictionary

The database schema is defined in database.py. SQLite's PRAGMA foreign_keys = ON is enforced on every request connection. Indexes are established on frequently queried columns (categories, customer relations, and order lookups).

4.3 Database Indexing Plan

  • idx_products_category ON products(category): Optimizes category browsing and filtered catalog searches.
  • idx_orders_customer ON orders(customer_id): Speeds up customer order history retrieval (/orders).
  • idx_order_items_order ON order_items(order_id): Accelerates order item lookups for invoices and seller views.

5. Subsystems & Functional Specifications

5.1 Authentication, Authorization & Session Security

User access is segregated strictly between Customer and Seller roles:

  • Authentication: Passwords are submitted via HTTPS POST, immediately converted into salted hashes using generate_password_hash, and compared via constant-time comparison in check_password_hash.
  • Session Storage: User authentication tokens and cart state are preserved in cryptographically signed client cookies using Flask’s app.secret_key.
  • Route Guards: Protected endpoints use Python decorators:
    • @login_required: Ensures the user is logged in before accessing personal profiles or checkout.
    • @seller_required: Enforces session['user']['role'] == 'seller'. Customers attempting to access seller portals receive a 403 Forbidden response.
    • @customer_required: Restricts checkout and order placement actions exclusively to buyers.

5.2 Product Catalog, Dynamic Search & Safe Sorting

The catalog engine supports free-form keyword search and category selection:

  • SQL Injection Shield: Rather than injecting raw user strings into SQL ORDER BY clauses, ShopLite employs an immutable whitelist dictionary: 
    SORT_ORDERS = {
    "newest": "p.created_at DESC, p.id DESC",
    "price_asc": "p.price ASC, p.id ASC",
    "price_desc": "p.price DESC, p.id ASC",
    "name_asc": "p.name COLLATE NOCASE ASC",
}
  • Search Query Execution: Parameterized LIKE ? search patterns match across both product names and descriptions simultaneously.
  • Category Visual Identifiers: Each category is paired with an intuitive emoji placeholder (💻 Electronics, 📚 Books, 🍳 Home & Kitchen, 👕 Fashion, ⚽ Sports, 💄 Beauty) rendered via custom Jinja2 template filters.

5.3 Session Cart Management with Defensive Clamping

The shopping cart is maintained in client sessions as {product_id: quantity}. To prevent stale-data exploitation (e.g., placing an order for items that have been bought out or deleted):

  • Whenever the cart is loaded (cart_items()), the system cross-references each product ID against the live database.
  • If a product was deleted or marked is_active = 0, it is dropped from the cart with an alert to the user.
  • If the requested quantity exceeds the current stock, the cart quantity is automatically clamped down to available stock, accompanied by a warning notification.

5.4 ACID Transactional Checkout Engine

The checkout process is the most mission-critical operation in an e-commerce platform. To prevent concurrency race conditions (such as overselling zero-stock inventory), app.py executes an explicit database transaction: 

  [ User Submits Shipping Address & Clicks 'Place Order' ]
                          |
                          v
         [ Execute: conn.execute("BEGIN") ]
                          |
                          v
         [ Iterate through each cart item: ]
         SELECT stock, is_active FROM products WHERE id = ?
                          |
           +--------------+--------------+
           |                             |
     [ Stock < Qty? ]             [ Stock >= Qty ]
           |                             |
           v                             v
   [ Flash Error ]            [ Deduct stock in DB: ]
   [ ROLLBACK ]               UPDATE products SET stock = stock - ?
           |                             |
           |                  [ Insert master order record: ]
           |                  INSERT INTO orders ...
           |                             |
           |                  [ Insert line items: ]
           |                  INSERT INTO order_items ...
           |                             |
           |                  [ Commit Transaction: ]
           |                  conn.execute("COMMIT")
           |                             |
           +-----------------------------+
                          |
                          v
        [ Empty session cart -> Redirect to /orders/ ]

5.5 Seller Portal & Inventory Lifecycle

Sellers possess full lifecycle authority over their merchandise:

  • Create: Form validation ensures title, description, category, positive price, and non-negative initial stock.
  • Edit & Restock: Sellers can update prices, adjust inventory upon receiving new shipments, or modify descriptions.
  • Soft Deletion: Items are never permanently purged from SQL if they are associated with existing order history. Instead, is_active is set to 0, hiding them from customer searches while preserving historical order invoices.
  • Fulfillment & Dispatch: Sellers can review incoming orders and update statuses across the complete delivery lifecycle.

7. Security Hardening & Defenses

Threat Vector Mitigation in ShopLite Technical Verification
SQL Injection (SQLi) Complete elimination of string concatenation in database statements. All user inputs are passed via SQLite parameter tuples (? placeholders). Verified across all SELECT, INSERT, UPDATE, and DELETE statements in app.py and database.py.
Cross-Site Scripting (XSS) Jinja2 template auto-escaping enabled by default. User names, product descriptions, and shipping addresses are rendered safe. Verified in all template files in /templates.
Credential Exposure Passwords are never stored in plaintext. Secure salt and cryptographic hashing are applied using standard cryptographic algorithms. Verified via Werkzeug PBKDF2/scrypt implementation.
Broken Object Level Authorization (BOLA) Sellers cannot edit, view, or alter products owned by other sellers. Queries enforce WHERE id = ? AND seller_id = ?. Verified in seller_product_edit and seller_product_delete.

8. Installation, Execution & Deployment Guide

8.1 Local Development Setup

Follow these steps to set up and run ShopLite on any local operating system:

# 1. Clone the repository from GitHub
git clone https://github.com/shreyascd/online-marketplace.git
cd online-marketplace

# 2. Create and activate a Python virtual environment
python -m venv .venv
# On Windows:
.venv\Scripts\activate
# On Linux / macOS:
source .venv/bin/activate

# 3. Install dependencies
pip install -r requirements.txt

# 4. Launch the application
python app.py

Once launched, open your web browser and navigate to: http://127.0.0.1:5000

9. Future Engineering Roadmap

The following extensions are planned for upcoming iterations of ShopLite:

  1. Payment Gateway Integration: Integrating Stripe and Razorpay SDKs with webhook listeners to support live credit cards, UPI, and net banking.
  2. Cloud Asset Storage: Offloading image uploads to Amazon S3 or Cloudflare R2 with image resizing pipelines.
